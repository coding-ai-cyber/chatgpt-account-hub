# 中英文切换设计

**日期：** 2026-09-14
**状态：** 已确认，待实现

## 目标

为 Codex Switcher 增加中文和英文切换。首次启动及没有语言字段的旧配置默认使用中文；用户主动选择 English 后，应用在后续启动中保持英文。

## 用户体验

在现有 Settings 弹窗顶部增加「语言 / Language」选择框，提供「中文」和「English」两个选项。选择后立即刷新当前界面，不需要重启。

翻译范围包括主窗口、设置弹窗、账户卡片、添加账户、导入导出、用量统计、Warm-up、错误提示、更新提示、托盘弹窗和应用自定义托盘菜单。账户名、动态数值、日期、时间和百分比保留原有数据，仅翻译周围的说明文案。操作系统提供的原生编辑菜单继续使用系统语言。

## 方案

使用项目内置的轻量翻译字典，不引入第三方国际化依赖。

- 前端提供统一的语言类型、翻译字典和 `useLanguage` 状态接口。
- 主窗口入口和独立托盘窗口都挂载同一个语言状态提供器。
- Rust 后端将语言写入已有的 `~/.codex-switcher/settings.json`，作为桌面端和托盘的共享来源。
- 语言变更广播已有的 `app-settings-changed` 事件，使已打开的主窗口和托盘弹窗同步刷新。
- 后端自定义菜单根据当前语言重建；Web 模式的 `/api/invoke/*` 同步支持语言读写命令。

## 数据模型与兼容性

在 Rust 的 `AppSettings` 增加语言字段，序列化值为 `zh-CN` 或 `en`。字段使用默认函数提供 `zh-CN`，因此旧版设置文件无需迁移即可得到中文默认值。读取到其他值时也回退到 `zh-CN`。

建议的设置片段：

```json
{
  "tray_display_mode": "active_usage_text",
  "dock_display_mode": "show_in_dock",
  "close_behavior_prompt_enabled": true,
  "language": "zh-CN"
}
```

## 组件与数据流

```text
Settings 语言选择
       ↓
set_language → settings.json
       ↓
app-settings-changed
       ↓
主窗口、托盘弹窗、原生自定义菜单同步刷新
```

后端新增读取/设置语言的命令，并在 Tauri 命令注册表和 Web 命令分发器中注册。设置命令负责校验值、保存设置、广播事件，并触发桌面自定义菜单重建。

前端翻译模块提供：

- `Language` 类型和默认语言常量；
- 语言值规范化函数；
- 英文和简体中文翻译字典；
- 按 key 返回当前语言文本的翻译函数；
- 语言状态、初始化、持久化和事件同步逻辑。

翻译 key 在两种语言中必须保持一致。运行时找不到翻译时回退到英文，避免出现空白文案。

## 测试与验收

新增纯函数测试，覆盖：

1. 未设置语言时默认 `zh-CN`；
2. 合法语言值可正常规范化；
3. 非法语言值回退到 `zh-CN`；
4. 中英文翻译 key 集合一致。

验收步骤：

1. 启动应用，确认首次界面为中文；
2. 在 Settings 中切换 English，确认主窗口、设置、托盘弹窗和自定义托盘菜单更新；
3. 切回中文，确认动态账户数据仍然保留；
4. 重启应用，确认上一次选择被保留；
5. 运行 TypeScript 构建和 Rust 测试，确认现有账户、OAuth、用量、Warm-up 和切换逻辑未回归。

## 非目标

- 不改动账户凭据、OAuth 流程、用量接口或账户切换逻辑。
- 不翻译用户自定义账户名、服务端返回的计划名称和错误原文中的专有内容。
- 不改变操作系统原生菜单的语言策略。
