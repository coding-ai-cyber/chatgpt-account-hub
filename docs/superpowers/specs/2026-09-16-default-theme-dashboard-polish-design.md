# 默认主题仪表盘优化设计规格

**状态：** 设计已确认，等待书面规格审核

**日期：** 2026-09-16

**基线：** 已实现的五页面 AppShell、13 主题系统和当前账户仪表盘

## 1. 背景

现有实现已经完成固定侧栏、顶部工具栏、独立页面、主题令牌和当前账户仪表盘，但在约 `888px` 宽的实际窗口中出现明显响应式缺陷：侧栏被媒体查询强制缩至 `72px`，文字却只在 React 的手动 `collapsed` 状态为真时隐藏，导致中文菜单被压成竖排并产生横向滚动条。

当前账户页同时存在卡片层级过碎、额度区横向空间利用不足、操作按钮权重相近、灰色指标块对比不足，以及“峰值日”标签下展示 Tokens 数值的语义错误。默认主题整体更接近后台原型，尚未达到最初参考图的柔和渐变、精致大卡片效果。

当前工作区包含其他模型尚未提交的实现改动。优化必须在现有实现上增量完成，不回退五页面架构、主题系统或业务能力，也不覆盖无关改动。

## 2. 目标

1. 彻底修复侧栏在 `600px–1023px` 窗口范围内的文字挤压和横向溢出。
2. 将默认主题升级为已确认的“柔和渐变仪表盘”视觉方向。
3. 将账户身份、快捷操作、额度环和双周期额度整合为一张主视觉卡。
4. 减少首页卡片碎片，建立清晰的主卡、摘要、活动和建议四级信息层次。
5. 修正首页统计标签与数据类型不匹配的问题。
6. 保持其余 12 种主题、五个独立页面、托盘同步和所有账户业务功能不变。
7. 为截图对应宽度和支持的最小窗口补充可重复的视觉与溢出验证。

## 3. 非目标

- 不重新设计其他账户、使用统计、帮助中心和设置页面的业务结构。
- 不修改 Rust 命令、账户存储、OAuth、令牌刷新或额度接口。
- 不删除、重命名或合并现有主题 ID。
- 不将默认主题改成高强度玻璃拟态；高模糊和强透明效果继续由 `glass` 主题承担。
- 不在首页新增后端当前没有提供的数据。
- 不通过提高最小窗口宽度来掩盖响应式问题。

## 4. 已确认的视觉方向

默认主题采用柔和渐变仪表盘：

- 应用背景以浅灰蓝为基底，在右上和内容区边缘加入低饱和蓝紫光晕。
- 主要表面使用接近白色的轻透明背景、细边框和柔和阴影。
- 主强调色为克制的蓝色；额度健康状态使用薄荷绿。
- 圆角保持现代但不过度膨胀：控件约 `10px`，普通卡片约 `14px`，主卡约 `18px`。
- 依靠间距、背景层次和字号建立层级，不用大量重复粗边框。
- 主界面保持专业工具感；插画和更强玻璃效果留给现有个性主题。

已确认的视觉稿位于本地视觉伴侣会话：

`/.superpowers/brainstorm/367-1789521412/content/default-theme-layout.html`

视觉稿仅作为布局和层级基准，不直接复制其中的示例数字或字符图标。

## 5. 侧栏响应式设计

### 5.1 断点规则

- 宽度不小于 `1024px`：侧栏默认展开，宽度 `188px`；用户可以手动折叠到 `72px`。
- 宽度 `768px–1023px`：侧栏强制使用紧凑模式，宽度 `72px`。
- 宽度小于 `768px`：侧栏离开文档流，通过顶部菜单按钮打开覆盖式抽屉。

### 5.2 状态规则

组件必须区分：

- `userCollapsed`：用户在宽屏主动保存的折叠偏好。
- `compactViewport`：由媒体查询决定的自动紧凑状态。
- `effectiveCollapsed = userCollapsed || compactViewport`：实际渲染状态。

CSS 与 JSX 都只依据 `effectiveCollapsed` 输出紧凑结构，禁止出现“宽度缩小但文字仍渲染”的中间状态。窗口从紧凑范围恢复到宽屏时，重新应用用户之前保存的 `userCollapsed` 偏好。

### 5.3 紧凑模式内容

紧凑侧栏中：

- 隐藏品牌文字、副标题、菜单文字、选中箭头和底部账户文字。
- 保留应用标志、五个导航 SVG 图标和底部账户头像。
- 每个按钮使用 `title` 与可访问名称提供完整含义。
- 图标按钮水平居中，点击区域不小于 `40×40px`。
- 导航容器使用 `overflow-x: clip` 或等效安全规则，不能产生水平滚动条。

展开侧栏中删除重复的 `Codex Switcher` 导航分组标题，只保留顶部品牌区和菜单。底部账户摘要仅展示当前账户，不重复当前页面名称。

### 5.4 溢出约束

- `.app-shell`、`.app-main`、`.app-content` 和主卡网格的所有可收缩子项设置 `min-inline-size: 0`。
- 邮箱、账户名称和不可分割标识使用 `overflow-wrap: anywhere`；普通说明文本不使用全局 `word-break: break-all`。
- 页面根节点和侧栏必须满足 `scrollWidth <= clientWidth`。
- 不能用对整个页面盲目 `overflow: hidden` 的方式裁掉必要操作。

## 6. 顶部工具栏

顶部工具栏保持页面标题、Codex 运行状态和全局操作，但重新校准权重：

- “添加账户”是唯一持续使用实心主色的顶部按钮。
- 隐藏信息、刷新全部和全部预热使用图标按钮；预热保留柔和警示色。
- 导入、导出和其他低频操作保留在“更多”菜单。
- 工具栏在空间不足时优先保留页面标题、运行状态和添加账户；低频按钮允许进入更多菜单，不换行成两排。
- 标题栏与工具栏保持独立职责：标题栏只管理窗口，工具栏只管理应用。

## 7. 当前账户主卡

### 7.1 主卡结构

当前分离的账户资料卡和额度卡合并为一个 `CurrentAccountHero`：

1. **账户头部：** 头像、名称或邮箱、当前状态、套餐、订阅日期和快捷操作。
2. **额度主体左侧：** 周额度环、准确的周期说明和健康状态。
3. **额度主体右侧：** 5 小时与 7 天额度条、剩余百分比、剩余时间和重置时间。

主卡在宽屏使用左右布局；内容宽度不足时额度环位于上方，两条额度位于下方。任何断点下都不能裁剪账户名称、重置时间或操作按钮。

### 7.2 额度环规则

- 优先展示 7 天额度；不存在时回退到 5 小时额度。
- 环中心同时展示百分比和周期标签，例如“周额度剩余”。
- 颜色使用语义状态：健康为薄荷绿、临近耗尽为琥珀、耗尽为红色。
- 缺失数据展示不可用状态，不把未知值显示为 `0%`。
- 环形图继续使用轻量 CSS 或 SVG，不引入图表库。

### 7.3 快捷操作

主卡直接显示：

- 在浏览器打开。
- 刷新账户。
- 预热。
- 更多。

遮罩账户、自动预热、查看详细信息和删除进入“更多”菜单。删除使用危险色，并继续要求二次确认。隐藏操作不会从应用中移除，只改变默认可见层级。

## 8. 摘要与活动区

### 8.1 四项首页摘要

首页固定展示：

- 生命周期 Tokens。
- 今天 Tokens。
- 最近 7 天 Tokens。
- 当前连续使用天数。

四项在宽屏单行展示，在中等宽度两列，在最小宽度单列或两列自适应。最长任务、最近 30 天和其他次级数据留在完整统计页面。

### 8.2 最近活动

最近活动展示：

- 快速模式占比。
- 线程总数。
- 峰值日期。

`峰值日期` 从 `stats.daily` 中选择 Tokens 最大的有效日期，并按当前语言格式化日期。若要展示峰值 Tokens，必须使用独立标签“峰值日用量”，不能把 Tokens 值放在“峰值日期”下面。没有每日数据时显示“暂无数据”。

### 8.3 使用建议

右侧使用建议只基于当前已有额度数据生成保守文案：

- 额度健康：提示当前无需切换。
- 任一窗口接近耗尽：提示关注最近重置时间。
- 数据不可用：提示刷新账户。

建议不进行未来额度预测，也不承诺可用时长。

## 9. 默认主题令牌调整

只修改默认主题的语义令牌和默认主题专属装饰：

- `--app-bg`：浅灰蓝基底。
- `--app-bg-image`：两层低饱和径向渐变。
- `--sidebar-bg`、`--toolbar-bg`：高可读性的浅色半透明表面。
- `--surface-primary`：接近白色。
- `--surface-secondary`：冷灰蓝辅助面。
- `--accent`：主蓝色。
- `--success`：薄荷绿。
- `--border-subtle`：低对比冷灰边框。
- `--shadow-card`：短距离、低透明阴影。
- `--radius-control`、`--radius-card`：与已确认视觉稿一致。

`glass`、`illustrated`、`graphite`、`mint` 和其余主题继续覆盖自己的令牌。默认主题的布局优化必须在这些主题中保持结构可用，但不强迫所有主题呈现相同渐变。

## 10. 组件边界

优化主要涉及：

| 路径 | 责任 |
| --- | --- |
| `src/app/AppShell.tsx` | 响应式侧栏状态、抽屉开关和应用框架 |
| `src/components/layout/Sidebar.tsx` | 根据实际紧凑状态渲染展开或图标结构 |
| `src/components/layout/TopToolbar.tsx` | 调整操作权重和窄宽度降级 |
| `src/pages/CurrentAccountPage.tsx` | 组合新的主卡、摘要、活动和建议区 |
| `src/components/dashboard/CurrentAccountHero.tsx` | 账户身份、双周期额度和快捷操作 |
| `src/components/dashboard/QuotaRing.tsx` | 额度环及健康状态 |
| `src/components/dashboard/MetricCard.tsx` | 四项摘要卡 |
| `src/lib/format.ts` | 日期、Tokens 和空值格式化 |
| `src/styles/tokens.css` | 默认主题令牌 |
| `src/styles/layout.css` | 侧栏、主卡和页面响应式布局 |

现有账户命令处理器继续由 `App.tsx` 提供。新组件只接收数据和回调，不直接调用 Tauri 命令。

## 11. 数据流与语义

```text
useAccounts / useAccountUsageStats
  → App.tsx 提供账户操作回调
  → CurrentAccountPage 计算首页展示模型
  → CurrentAccountHero / MetricCard 只负责渲染
```

页面展示模型必须区分：

- 数值为 `0`。
- 数值未知或字段缺失。
- 请求正在加载。
- 请求失败。

未知数据使用“暂无数据”或破折号，不能格式化成 `0`。峰值日期计算只接受可解析日期和有限非负 Tokens 值；并列时选择最近日期。

## 12. 加载、错误与交互

- 主卡加载骨架与最终主卡尺寸一致，防止布局跳动。
- 单账户刷新时只更新主卡和相关统计，不遮挡整个应用。
- 统计加载失败时，主卡额度仍可使用；活动区显示局部错误和重试入口。
- “更多”菜单关闭后焦点返回触发按钮。
- 所有图标按钮具有 `aria-label`、提示、hover、active、disabled 和 `focus-visible` 状态。
- 页面动画继续遵守 `prefers-reduced-motion`。

## 13. 测试与视觉验证

### 13.1 单元与组件测试

- 自动紧凑状态与用户折叠偏好组合正确。
- 窗口恢复到宽屏后恢复用户偏好。
- 紧凑侧栏不渲染可见菜单文字，导航仍有可访问名称。
- 额度环优先 7 天、回退 5 小时，并正确处理缺失数据。
- 峰值日期返回日期而非 Tokens 数值；无数据和并列规则正确。
- 统计 `0` 与未知值显示不同。
- 删除等危险操作只在更多菜单中出现并继续触发确认。

### 13.2 响应式与视觉回归

使用固定测试账户数据检查以下视口：

- `600×500`。
- `888×693`，对应发现问题的截图尺寸。
- `900×700`。
- `1120×760`。
- `1440×900`。

在浏览器自动化中断言：

```text
document.documentElement.scrollWidth <= document.documentElement.clientWidth
sidebar.scrollWidth <= sidebar.clientWidth
main.scrollWidth <= main.clientWidth
```

为 `888×693` 和 `1120×760` 保存默认主题截图基准，并人工检查默认、glass、graphite、mint 和 illustrated 五个代表主题。

### 13.3 构建验证

1. 运行现有全部 Node 测试。
2. 运行新增布局、格式化和响应式测试。
3. 运行 `pnpm build`。
4. 运行 `cargo check --manifest-path src-tauri/Cargo.toml`。
5. 运行 Windows Tauri 正式打包。
6. 安装 EXE，验证侧栏、主题持久化、托盘、账户刷新、预热和页面切换。

## 14. 验收标准

1. `888×693` 窗口中侧栏文字不再竖排，侧栏和页面均无横向滚动条。
2. `600×500` 最小窗口中的所有核心操作可以通过抽屉或更多菜单访问。
3. 默认主题与已确认视觉稿保持一致的柔和渐变、大主卡和轻量层级。
4. 当前账户资料、额度环和两个额度周期在同一主卡中完整展示。
5. 首页只保留四项高价值摘要，其他统计仍可在完整统计页查看。
6. “峰值日期”显示日期；Tokens 数据不会使用日期标签。
7. 添加账户是顶部唯一持续使用实心主色的操作。
8. 其余 12 种主题、五个页面、托盘同步和账户业务行为没有回归。
9. 自动化测试、前端构建、Rust 检查和 Windows Tauri 打包通过。
