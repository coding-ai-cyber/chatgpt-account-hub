# Codex Switcher 可切换主题与侧栏仪表盘设计规格

**状态：** 已完成设计评审，等待用户审核书面规格  
**日期：** 2026-09-15  
**目标平台：** Windows Tauri 桌面应用；同时保持 macOS、Linux 和浏览器仪表盘兼容

## 1. 背景与结论

Codex Switcher 具有完整的 Tauri 2、React 19、TypeScript 和 Tailwind CSS 源码，因此界面应从源码重构并重新打包，不直接修改已编译的 EXE 二进制。

当前主窗口是单页滚动布局，主要 UI 与大量业务协调逻辑集中在 `src/App.tsx`。工作区中已经存在尚未提交的皮肤系统雏形，包括主题本地存储、`data-skin` 属性、主窗口与托盘同步事件、主题选择界面、12 个主题 ID，以及四张本地场景背景图。本次设计保留这些已有工作，在其上整理架构、补齐参考图中的四个重点风格并重构页面展示，不覆盖或丢弃现有功能改动。

项目当前前端构建命令 `pnpm build` 已通过。正式实施仍需对工作区中的既有未提交改动逐项确认归属，只提交本项目任务实际修改的文件。

## 2. 目标

1. 将主窗口改造成固定应用框架、左侧菜单和独立内容页组成的桌面仪表盘。
2. 支持“当前账户、其他账户、使用统计、帮助中心、设置”五个独立页面即时切换。
3. 保留现有皮肤，并将参考图中的玻璃拟态、卡片插画、深色主题和极简清新作为四个重点主题。
4. 使主题统一覆盖主窗口、页面、弹窗和托盘弹窗；托盘不加载大幅背景图。
5. 保持账户登录、账户切换、额度查询、统计、预热、关闭 Codex、托盘与自动更新等业务行为不变。
6. 提升信息层级、窗口适配、可访问性、错误反馈和视觉一致性。
7. 从源码生成可安装的 Windows EXE，并完成真实安装环境验收。

## 3. 非目标

- 不修改 Rust 侧账户存储格式、OAuth 流程、令牌刷新规则或额度接口语义。
- 不新增跨账户额度合计；不同账户和不同订阅周期不会直接相加。
- 不把每个菜单项做成独立 Tauri 原生窗口。
- 不引入完整 UI 组件库、全局状态管理库或 React Router。
- 不在统计数据缺失时展示模拟数字。
- 不删除已有主题 ID，也不使用户已经保存的主题配置失效。

## 4. 已确认的核心决策

### 4.1 单窗口 AppShell

应用使用一个 Tauri 主窗口。`AppShell` 负责自定义标题栏、侧栏、顶部工具栏、主内容区、全局 Toast 和模态框出口。菜单切换通过 React 内部页面状态实现，不刷新窗口，也不重新初始化账户状态。

选择该方案的原因：

- 符合参考图的固定侧栏和单窗口内容切换模式。
- 无需额外路由依赖，也不产生桌面端无实际收益的 URL 历史管理。
- 可直接复用现有 `useAccounts` 状态、命令处理器和 Tauri 事件监听。
- 页面组件可以独立测试，同时保持应用级操作只有一个数据源。

### 4.2 独立页面而非锚点滚动

菜单 ID 固定为：

```ts
export type PageId =
  | "current-account"
  | "other-accounts"
  | "usage-stats"
  | "help"
  | "settings";
```

页面切换时保留本次运行中的滚动位置和页面局部筛选条件。当前页面写入 `codex-switcher-active-page`；读取到未知值时回退到 `current-account`。

### 4.3 统计查看对象与登录账户分离

“使用统计”页面维护独立的 `viewedAccountId`。默认值是当前活动账户；用户在统计页选择其他账户时，仅请求并展示该账户统计，不调用账户切换命令，也不改写活动账户。

### 4.4 本地帮助中心

帮助内容随应用打包并支持中文和英文。在线入口仅作为补充：

- 在线文档：`https://github.com/Lampese/codex-switcher#readme`
- 反馈问题：`https://github.com/Lampese/codex-switcher/issues`
- 检查更新：复用现有应用内更新检查能力

## 5. 信息架构与页面设计

### 5.1 应用框架

主窗口由以下区域组成：

1. **原生感标题栏：** 保留窗口拖动、双击最大化、最小化、还原和关闭能力。
2. **左侧菜单：** 应用标识、五个页面入口、折叠控制，以及底部当前账户摘要。
3. **顶部工具栏：** 当前页面标题、Codex 运行状态、全局快捷操作。
4. **主内容区：** 一次只渲染当前页面的可见内容。
5. **全局反馈层：** Toast、确认模态框、更新提示和账户添加流程。

顶部快捷操作包括隐藏/显示全部账户信息、刷新全部、全部预热、添加账户和更多操作。搜索、导入、导出等低频入口归入“更多操作”，避免顶部工具栏拥挤。

### 5.2 当前账户页

当前账户页是默认首页，展示：

- 账户名称、邮箱、活动状态、套餐、重置积分和订阅状态。
- 一个带明确周期标签的额度环。优先显示 7 天额度；若 7 天窗口不存在，则显示 5 小时额度；两者都不存在时显示不可用状态。
- 5 小时与 7 天额度条、剩余百分比和准确的重置时间。
- 最近活动、生命周期令牌、今日令牌、近 7 天令牌、连续使用天数和最长任务等摘要。
- 打开浏览器、刷新、预热、自动预热、账户信息遮罩和查看更多统计操作。

首页只展示摘要。点击“查看完整统计”切换到 `usage-stats` 页面，并把当前活动账户设为统计查看对象。

### 5.3 其他账户页

其他账户页提供：

- 账户搜索。
- 按重置期限、剩余额度和订阅到期时间排序。
- 网格视图与紧凑列表视图切换。
- 每个账户的身份信息、套餐、5 小时与 7 天额度、更新时间和订阅状态。
- 切换账户、在浏览器打开、刷新、预热、自动预热、查看统计、重命名和删除操作。

点击卡片主体打开该账户的详情抽屉或展开区；具体操作按钮停止事件冒泡，避免将“查看详情”与“切换账户”混为一次点击。删除继续要求二次确认。账户数量为零或搜索无结果时显示有明确下一步操作的空状态。

### 5.4 使用统计页

页面顶部使用账户选择器，默认选择当前活动账户。所选账户 ID 可在本地记忆，但当账户已被删除或不可用时自动回退到当前活动账户或账户列表第一项。

统计内容包括：

- 生命周期、今日、近 7 天、近 30 天和最长任务。
- 连续使用天数、峰值日期和使用频率。
- 令牌活动趋势，可选择现有数据支持的时间范围。
- Fast Mode、推理活动、Skills 使用和线程数等活动信息。
- 常用集成排行。
- 独立刷新按钮和最近更新时间。

选择统计对象不触发登录账户切换。仅在页面首次展示、选择账户改变或用户主动刷新时请求统计，避免隐藏页面持续重复请求。

### 5.5 帮助中心页

本地帮助页由可折叠章节组成：

1. 快速入门。
2. 添加、切换、重命名、导入和导出账户。
3. 5 小时与 7 天额度、重置时间及手动重置积分说明。
4. 手动、自动和定时预热说明。
5. Codex 进程关闭与重开行为。
6. 托盘、Dock 和后台运行方式。
7. 常见错误与处理方法。
8. 隐私说明与本地数据位置。

页尾提供在线文档、反馈问题和检查更新三个入口。外部链接统一通过现有 `openExternalUrl` 能力打开。

### 5.6 设置页

设置从当前模态框迁移为独立页面，按以下分组展示：

- **外观：** 主题分组、真实缩略预览、默认主题明暗选择、减少动态效果说明。
- **语言：** 简体中文与英文。
- **托盘与 Dock：** 托盘展示模式和 macOS Dock 模式。
- **账户切换：** 与账户切换相关的行为选项。
- **Codex 关闭与重开：** 询问、正常关闭、强制关闭和桌面应用重开偏好。

设置修改保持现有即时保存行为。保存失败时错误显示在对应设置项附近，不关闭或跳离页面。需要确认的危险操作继续使用模态框。

## 6. 响应式窗口行为

建议主窗口默认尺寸从 `900×700` 调整为 `1120×760`，继续兼容现有 `600×500` 最小尺寸。

- **宽度不小于 1024px：** 显示约 208px 的完整侧栏，菜单包含图标和文字。
- **宽度 768px–1023px：** 显示约 72px 的图标侧栏，文字通过无障碍标签和提示提供。
- **宽度小于 768px：** 固定侧栏替换为可关闭的覆盖式抽屉，顶部显示菜单按钮。
- 页面主体不得产生整页横向滚动；统计表格和特殊长内容只能在自身容器滚动。
- 标题、邮箱、套餐名称和中英文长文本必须使用合理换行或截断，并提供完整内容提示。

### 7.2 明暗模式规则

`default` 主题继续支持用户当前保存的 `light`/`dark` 模式。其他主题使用自身固定的视觉模式和 `color-scheme`，但不会删除用户保存的默认主题明暗偏好；用户返回 `default` 时恢复该偏好。独立的明暗切换入口移动到设置页，并只在 `default` 被选择时启用，避免固定深色或固定浅色主题出现语义冲突。

### 7.3 语义化令牌

组件不再通过覆盖整套 Tailwind 灰阶变量和大量 `!important` 选择器换肤。主题统一实现以下语义令牌：

```css
--app-bg;
--app-bg-image;
--sidebar-bg;
--toolbar-bg;
--surface-primary;
--surface-secondary;
--surface-elevated;
--text-primary;
--text-secondary;
--text-muted;
--accent;
--accent-contrast;
--success;
--warning;
--danger;
--border-subtle;
--border-strong;
--focus-ring;
--shadow-card;
--shadow-overlay;
--radius-control;
--radius-card;
--blur-surface;
```

共享组件使用 `app-*`、`surface-*`、`text-*` 等语义类。每个主题文件只定义令牌和少量确实属于该主题的装饰效果。

### 7.4 主题应用与同步

主题选择流程为：

```text
设置页选择
  → 校验 SkinId
  → 写入 document.documentElement.dataset.skin
  → CSS 令牌即时生效
  → 写入 localStorage
  → 发出 skin-changed Tauri 事件
  → 托盘弹窗读取同一主题并应用简化色板
```

托盘同步主题的配色、边框、圆角、焦点和按钮状态，但不加载场景大图或高成本模糊背景。读取到无效主题时回退 `default`，并在下一次成功保存时覆盖无效值。

### 7.5 主题资源

- 所有运行时资源随应用本地打包，不依赖远程字体、图片或 CDN。
- 场景背景转换为 WebP；每张以当前 1344×768 视觉需求为基准压缩，目标单张不超过 500KB。
- 卡片插画使用项目自有或许可明确的本地资源，并在 `public/themes/SOURCES.md` 记录来源与再分发条件。
- 背景图仅装饰主内容，不承载文字或状态信息。

## 9. 状态与数据流

### 9.1 账户数据

```text
Rust/Tauri command or browser API
  → src/lib/platform.ts
  → src/hooks/useAccounts.ts
  → App.tsx application controller
  → current page props
  → presentational components
```

`useAccounts` 继续作为账户列表、活动账户和额度数据的唯一来源。页面组件不直接复制账户状态，也不新增敏感账户数据的本地持久化。

### 9.2 UI 状态

本地持久化仅保存非敏感 UI 偏好：

- 当前页面：`codex-switcher-active-page`
- 主题：继续使用 `codex-switcher-skin`
- 默认主题明暗：继续使用 `codex-switcher-theme`
- 侧栏折叠：`codex-switcher-sidebar-collapsed`
- 其他账户视图：`codex-switcher-account-view`
- 其他账户排序：复用或统一现有排序存储键
- 统计查看账户：`codex-switcher-stats-account`

账户被删除后，依赖该账户 ID 的统计选择和展开状态在读取时自动失效，不阻断页面渲染。

## 10. 交互与反馈

- 页面切换使用 150–220ms 的轻量淡入和位移动画。
- `prefers-reduced-motion: reduce` 下取消非必要过渡，并直接渲染最终状态。
- 所有可点击项目具有 hover、active、disabled 和 focus-visible 状态。
- 图标统一使用内联 SVG 图标系统；不使用 Emoji 或字符作为正式操作图标。
- 纯图标按钮具有可访问名称和可见提示。
- 所有主要点击目标不小于 40×40px；空间允许时使用 44×44px。
- 页面切换后焦点移动到页面一级标题，抽屉关闭后焦点返回菜单按钮。
- 模态框打开时限制焦点在模态框内部，关闭后返回触发控件。

## 11. 加载、空状态和错误处理

### 11.1 加载

- 首次账户加载显示与最终布局同尺寸的骨架，避免布局跳动。
- 单账户刷新只让对应额度区域进入加载态，不遮挡整页。
- 统计页切换账户后保留页头和账户选择器，只替换统计内容骨架。

### 11.2 空状态

- 无账户：显示添加账户主操作和导入账户次操作。
- 搜索无结果：显示清除搜索条件操作。
- 统计不可用：解释支持条件，并提供刷新或返回账户页操作。
- 某个字段缺失：显示“暂无数据”，不以 `0` 冒充未知值。

### 11.3 错误

- 页面请求失败：在对应内容区域显示错误卡和重试按钮。
- 用户操作失败：通过全局 Toast 显示本地化错误摘要；控制台保留开发诊断信息。
- 设置保存失败：错误紧邻对应设置项，并保持用户当前选择可见。
- 危险操作：使用确认模态框；提交期间禁用重复操作。
- 主题资源加载失败：保留主题色板并回退为无背景图版本，不能导致界面空白。

## 12. 可访问性与文本

- 正文和主要控件文本对比度至少达到 4.5:1。
- 信息不能只依赖颜色表达；活动、告警和额度状态同时提供文字或图标。
- 侧栏使用导航语义，当前页面使用 `aria-current="page"`。
- 主题选择器使用单选语义；主题分组使用清晰的标题和数量。
- 中英文内容使用现有 i18n 体系，不在组件中散落硬编码页面文案。
- 正文字号不小于 14px；次要元数据不小于 12px。
- 键盘用户可以访问所有页面、菜单、选择器、按钮和折叠内容。

## 13. 性能设计

- 大背景图使用本地压缩 WebP，并避免在托盘和隐藏页面加载。
- `backdrop-filter` 只用于玻璃主题的顶层表面，不在嵌套卡片上重复叠加。
- 页面不可见时停止非必要动画和定时视觉更新。
- 统计请求由页面可见性、账户选择和显式刷新驱动，不因主题切换重新请求。
- 不默认对所有组件使用 `React.memo`；只在性能分析证明存在明显重复渲染成本时使用。
- 环形图用轻量 SVG 实现，不引入图表库。

## 16. 风险与控制措施

| 风险 | 控制措施 |
| --- | --- |
| 当前 `App.css` 有大量主题覆盖和 `!important`，继续叠加会产生选择器冲突 | 先建立语义令牌和共享类，再按主题迁移；每完成一个主题即删除对应旧覆盖 |
| `App.tsx` 体积过大，页面拆分时容易带来业务回归 | 保留应用控制器和现有处理函数，先抽纯展示组件，再移动页面局部状态 |
| 主题与独立明暗模式冲突 | 只有 `default` 支持明暗切换；固定主题声明自身模式 |
| 背景图增加安装包和渲染成本 | WebP 压缩、按需加载、托盘禁用背景图、限制模糊层数 |
| 工作区已有未提交修改 | 实施前记录基线，逐文件审查差异，提交时只暂存本任务文件 |
| 不同平台 WebView 渲染存在差异 | 以 Windows 为主要验收平台，同时执行浏览器、macOS 和 Linux 构建兼容检查 |

## 17. 验收标准

1. 五个左侧菜单均切换到独立页面，切换过程不刷新窗口。

9. 现有账户管理、切换、刷新、预热、关闭行为、重开、托盘和更新能力通过回归验证。

11. 生成的 Windows 安装包完成真实安装、启动、重启和卸载验证。
